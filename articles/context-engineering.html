病历不是越塞越好：医疗 Agent 的上下文预算该怎么花

读 Anthropic 上下文工程：从“全部告诉模型”到“在正确时刻提供证据”

胡浩源｜京东健康 AI 副总裁，医疗专病大模型 & AI 产品线负责人

医疗 Agent 一旦回答不准确，最直觉的改进常常是增加输入：再放几份指南，再补几段病历，再加一些注意事项。但上下文越长，模型就越可靠吗？

Anthropic 在 2025 年 9 月 29 日发布的《Effective context engineering for AI agents》给出了另一种工程视角：上下文是有限资源，目标不是装入最多信息，而是找到能够支撑目标行为的最小高信号信息集合。这里的“最小”不等于越短越好，更不能以压缩为名删除关键条件。

从京东健康的医疗 Agent 工程视角看，这篇文章的价值在于：它把问题从“如何写一句更好的提示词”，推进到“系统如何持续决定模型此刻应该看见什么”。

一、管理的不是一个 Prompt，而是整个工作状态

原文将上下文工程视为提示词工程的自然延伸。需要管理的不只有系统指令，还包括工具定义、外部数据、消息历史和工具返回结果。Agent 每执行一步，都会产生新的候选信息；这些信息是否继续进入下一轮，必须重新判断。

这与医疗任务十分相关。一个患者的历史材料可能很多，但当前任务究竟是整理复诊摘要、检查用药信息，还是构建科研队列，决定了证据的优先级。把全部材料平铺进去，并不会自动产生正确的重点。

我的理解是，上下文应像一个有边界的工作台，而不是仓库。工作台保留当前目标、已确认事实、必须遵守的约束、仍待解决的问题；原始资料则保留可追溯的访问入口。否则，模型可能把旧结论当成当前状态，也可能在大量正常描述中漏掉真正改变判断的异常。

二、即时加载不是取消检索，而是改变加载时机

原文提出 just-in-time 策略：先保留文件路径、查询或链接等轻量标识，在需要时通过工具加载具体内容。它同时明确讨论了混合策略——一部分资料预先提供，另一部分由 Agent 按需探索。

因此，把这篇文章理解成“RAG 已经过时”是不准确的。检索系统解决哪些资料可能相关；上下文工程还要解决何时加载、加载多少、怎样组织、什么时候移出。二者并不互斥。

医疗场景可以采用三层结构。以下是我的设计建议，而非原文实现：

  • 常驻层：当前任务、患者或研究对象标识、权限边界，以及经确认的关键约束。
  • 索引层：资料类型、时间、来源、版本和访问引用，不默认展开全文。
  • 证据层：为当前判断加载的原始片段，同时保留出处和适用条件。

例如，处理一项检查结果时，应把数值、单位、采集时间和参考范围作为一个整体加载，而不是只检索到一个数字。若来源缺失，状态应保持“待核实”，不能靠模型补全。

三、压缩最危险的不是少了一句话，而是改变了语义

针对长任务，原文讨论了上下文压缩、结构化笔记和子 Agent 架构。压缩保留关键决策与未解决问题；笔记将进展持久化到窗口之外；子 Agent 在独立上下文中完成局部探索，再返回精炼结果。

医疗任务不能机械照搬通用摘要。需要防止三种语义损失：把“未记录”压缩成“无”，把“待排除”压缩成“确诊”，以及把不同时间的观察合并成一个稳定事实。

因此，我建议把临床事实表示为带限定条件的记录，而不是只保留自然语言结论：

事实：某项检测结果
时间：采集时间与报告时间
来源：报告引用及版本
状态：已确认 / 待核实 / 来源冲突
限制：单位、适用范围、缺失字段

压缩前后的验收，也不应只比较文字相似度。更重要的是：时间关系是否保留，否定与未知是否区分，重要冲突是否仍可见，引用是否还能回到原文。精炼摘要可以作为导航，却不应成为无法追溯的唯一事实来源。

四、子 Agent 摘要需要交接协议

原文描述的子 Agent 模式，把详细探索留在局部上下文，主 Agent 只接收浓缩摘要。这样能减少信息干扰，但同样会形成信息瓶颈。

以医疗科研为例，如果一个子 Agent 负责队列构建，另一个负责统计分析，前者不能只返回“已得到可用样本”。交接至少应包含纳排标准版本、样本数变化、字段定义、缺失情况及未解决异常。否则，统计代码可能完全正确，却分析了错误的研究对象。

这里不应追求每份摘要都极短，而应明确每类任务必须交接的最小信息。高信号的含义，是能支撑下一步正确决策，而不是容易阅读。

五、上下文优化最终要接受任务验证

上下文变短、Token 变少，都是过程指标，不是成功本身。可以用同一组医疗任务比较不同策略：关键事实保留率、遗漏率、引用可追溯性、工具调用成本，以及完整任务的验收结果。

还应增加针对压缩的压力测试：先提供相互冲突的资料，再跨越多个会话，观察 Agent 是否仍保留冲突；先声明信息未知，再提供部分补充，观察它是否错误地填满剩余字段。

这些是本文提出的医疗工程验证方法，并非原文已有的临床证据。原文给出的原则仍需在具体任务、隐私约束和专家标准下检验。

医疗 Agent 的上下文工程，不是教系统“记住更多”，而是让系统知道：哪些事实现在必须看见，哪些证据需要随时取回，哪些不确定性绝不能在摘要中消失。
