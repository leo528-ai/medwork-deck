“已完成”不算完成：医疗 Agent 的评测要落到真实结果

读 Anthropic Agent Evals：把一次漂亮演示变成可重复的质量证据

胡浩源｜京东健康 AI 副总裁，医疗专病大模型 & AI 产品线负责人

一个科研 Agent 说“分析已经完成”，究竟意味着什么？是写出了一段看起来合理的结论，还是代码确实执行、统计口径正确、图表与数据一致，并生成了可验收的交付物？

Anthropic 在 2026 年 1 月 9 日发布的《Demystifying evals for AI agents》，最值得医疗工程团队认真对待的，是对 transcript 与 outcome 的区分：前者是执行过程的完整记录，后者是任务结束时环境中的实际状态。

原文用订票说明这一点：Agent 说已订票，不等于数据库中真的存在预订。放到医疗科研，同样不能把“我完成了分析”当成结果证据。

一、评测单位应是一项任务，而不是一段回答

原文区分 task、trial、grader 和 evaluation harness。一项 task 有输入与成功标准；一次 trial 是对该任务的一次尝试；grader 对过程或结果的某个方面评分；评测基础设施负责运行、记录和汇总。

这种拆分对医疗任务很重要。以“完成一项回顾性分析”为例，任务不应只给一句宽泛要求，也不应只用语言模型判断报告是否专业。输入应明确研究问题、数据版本、分析方案和交付要求；验收则要落到可检查的制品。

我的建议是至少分三层：代码检查验证执行和数据处理，结果检查验证样本数及统计表图一致性，专家评分检查方法是否适当、解释是否越过证据边界。这不是把一个复杂任务压成单一分数，而是让失败发生在哪一层可以被识别。

二、最终结果优先，但关键安全过程不能省略

原文提醒，不要把某一串固定工具调用顺序当成唯一正确路径。Agent 可能找到设计者没预想到的有效方案，过度刚性的评分会误判成功。

医疗场景应保留这种灵活性，同时划清边界。生成图表可以有不同实现；但获取数据的权限、关键方案的批准和影响临床决策时的医生审核，不是可以省略的“实现细节”。

因此，评测需要区分两类过程要求：一类只是参考路径，不宜强制；另一类是任务成立的必要条件，必须单独检查。不能因为最终报告漂亮，就抵消未经授权的数据访问。

一个设计示意是：

结果门槛：制品存在、可复现、统计与报告一致
安全门槛：权限有效、关键审批存在、无越界操作
质量维度：解释清楚、限制充分、引用支持结论
任务通过：结果门槛通过，并且安全门槛通过

质量分可以反映差异，但关键安全失败不能简单与文风得分平均。

三、会做一次，与每次可靠，是两件事

原文特别讨论 pass@k 与 pass^k。前者关心 k 次尝试中至少一次成功，后者关心 k 次是否全部成功。

假设每次成功概率为 75%，并暂且假设各次独立且概率稳定，尝试三次至少成功一次的概率约为 98.4%；三次全部成功的概率却只有约 42.2%。两者没有矛盾，只是回答不同问题。

科研代码探索允许多次尝试，但必须有办法识别正确结果，不能只挑一份最像成功的报告。面向医生的重复工作流，则不能用“多试几次总能对”替代可靠性要求。

这也意味着，多次运行必须从干净环境开始。原文指出，遗留文件、缓存、资源耗尽，甚至前次试验的 Git 历史，都可能污染结果。若多个试验共享同一个故障源，不能把它们当成独立证据。

四、能力集与回归集，承担不同职责

原文将评测分成能力评测与回归评测。能力集回答“还有什么做不好”，应该保留挑战；回归集回答“过去会做的是否还可靠”，用于守住已有质量。

从医疗 Agent 工程看，这能避免两种常见误区。第一，只保留已经做对的简单题，分数很高却无法指引改进。第二，每次都换更难的题，团队却无法知道某次更新是否破坏了已有能力。

我们可以把失败案例逐步沉淀为能力任务；当某类任务达到稳定要求，再进入回归集。模型、提示词、工具、Skills 或 Harness 的改动，都应运行同一套基线。任务也需要留出未参与调优的验证部分，避免把系统优化成只会做熟题。

Benchmark 的价值因此不只是排名，而是成为团队共同的验收语言：产品定义什么叫完成，医学专家定义什么不能错，工程团队用证据判断改动是否有效。

五、评分器本身也需要被验证

原文建议优先使用合适的确定性评分，在需要时使用模型评分，并以专家判断校准。对于不充分的信息，评分模型应允许返回 Unknown，而不是被迫给出确定结论。

医学任务尤其不能默认“模型裁判”就是客观真值。需要用明确的 rubric 分开评价证据支持、方法合理性与表达质量，并定期抽取通过和失败样本交给专家复核。

读执行记录仍然不可替代。一个失败可能来自 Agent，也可能来自错误题目、失效工具或过严的评分器。只有把这些原因分开，评测分数才有工程意义。

这篇文章不是医疗安全认证的方法，也不能取代临床验证。它提供的是一套更扎实的研发纪律：先定义成功，再设计证据，最后用可重复的试验判断进步。

医疗 Agent 最需要的，不是更自信地宣布“已完成”，而是让每一次完成都经得起追问。

原文来源：Mikaela Grace、Jeremy Hadfield、Rodrigo Olivares、Jiri De Jonghe，Demystifying evals for AI agents，Anthropic Engineering，2026 年 1 月 9 日。
