ENGINEERING NOTES / ANTHROPIC 工程解读

多 Agent 的价值，不是多几个角色，而是多几条有效调查路径

读 Anthropic《How we built our multi-agent research system》

胡浩源｜京东健康 AI 副总裁

给一个问题配上“专家、审稿人、主持人”，不一定得到更好的答案。角色名称不会自动带来独立证据，也不会消除重复搜索。

Anthropic 关于 Research 的工程文章，提供了一个更实在的观察：多 Agent 最擅长的，是把可并行的调查分给拥有独立上下文的工作单元，再把结果压缩、汇总。这是一种扩大信息处理容量的方法，不是让多个模型投票就接近真理。

一、90.2% 的提升，要与成本一起看

原文报告，以 Claude Opus 4 为主 Agent、Sonnet 4 为子 Agent 的系统，在内部研究评测上，相比单 Agent Opus 4 提升 90.2%。

这个数字不是准确率达到 90.2%，也不是提高 90.2 个百分点。它属于作者内部任务与配置下的相对表现，不能直接外推到医疗诊断。

更容易被忽略的是成本。作者观察到，Agent 的 token 用量通常约为普通聊天的 4 倍，多 Agent 系统约为聊天的 15 倍。多 Agent 的提升，一部分来自投入了更多计算和检索工作。

因此，我们要问的不是“多 Agent 是否先进”，而是：这项任务值得投入多少资源？相同预算下，增加子 Agent、换更强模型、改善工具，哪一项收益更大？

文章适合支持“并行研究可以提升覆盖面”，不适合支持“增加 Agent 数量必然提升性价比”。

二、真正的架构核心，是明确分工和独立上下文

Research 使用主 Agent 协调、子 Agent 调查的结构。主 Agent 制订策略，子 Agent 分别搜索和判断，结果回来后再决定是否补充调查，最后还有引用处理环节。

独立上下文的价值，在于避免所有信息竞争同一块工作空间。调查指南更新的人，不必反复阅读全部竞品材料；追查某项统计数据的人，可以沿着自己的证据链深入。

但独立上下文也会制造割裂。原文举了一个失败：模糊的“调查半导体短缺”指令，使一个 Agent 研究 2021 年汽车芯片危机，另两个却重复调查 2025 年供应链。

所以，任务描述至少要包含目标、时间范围、来源、输出格式和边界。“你是专家”不够，“请核对这个结论在指定时间窗内是否成立，返回原始出处与反例”才是可执行的分工。

三、搜索应该随证据变化，而不是不断增加关键词

原文将自己的多步骤搜索，与按相似度取回一组文本片段的静态检索作对比：搜索结果会改变下一轮调查方向。

这里的启发不是“所有 RAG 都错了”，而是单次召回不能替代证据闭环。RAG 是一类宽泛方法，Agentic Search 也不会天然消除幻觉。

站在医疗工程视角，我们需要更明确的停止条件：已经找到指南原文了吗？版本是否有效？适用人群一致吗？关键推荐有没有例外？存在冲突时是否需要人工判断？

这些是本文的领域延伸。我们追求的“确定性”，应落实为可检查的来源、适用条件和交付规则，而不是声称搜索过程已经没有概率性。

四、评测结果，而不是强迫所有 Agent 走同一条路

同一个研究问题，有人用三次搜索找到答案，有人需要十次。若评测只判断是否沿着预设路径调用工具，就可能把合理的新路径判成错误。

原文采用的评分维度包括事实准确性、引用准确性、完整性、来源质量和工具效率。它还强调人工测试：早期系统偏爱搜索排名较高的内容农场，却忽略学术 PDF 等更可靠的材料，这种偏差需要人发现。

我认为，医疗研究助手尤其需要把“结论对”和“证据对”分开。答案碰巧正确，但引用不能支撑它，仍然不应通过；找到权威指南，但忽略患者不在其适用范围，也不应通过。

多 Agent 之间的一致意见不是独立验证。它们可能共享同一个错误来源，甚至共享同一种模型偏差。关键是证据是否独立、冲突是否被保留，而非有多少个角色表示赞同。

五、值得并行的是调查，不一定是最终决策

下面是一种设计建议，不是原文已部署的医疗系统。

准备一项临床研究时，可以并行调查现有证据、终点定义与统计方法；每个子任务返回来源、结论、局限和未解决问题。涉及患者数据操作、分析方案变更及最终解释，则进入明确的串行确认和人工审核。

输出最好保存为独立制品，协调者接收路径与摘要，而不是把完整报告反复转述。原文也提出这一方式，以减少信息在多次传话中的损失。

同时，并行不应越多越好。任务高度依赖共享状态时，协调成本会迅速增加。一次统计分析尚未确定入组人群，就让多个 Agent 分头算结果，得到的可能只是互不兼容的表格。

真正可用的多 Agent 系统，还要处理检查点、失败恢复、版本升级和可观测性。原文对这些工程细节的重视，比角色编排更有价值。

我的结论是：多 Agent 的优势来自合理拆分后的信息增量，不来自角色数量。能并行的证据调查充分并行，必须一致的业务状态严格一致，应该由人决定的边界清楚交还给人。这样增加的才是执行能力，而不是更热闹的对话。
